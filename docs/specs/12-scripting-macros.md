# Scripting Macros

## Overview

A `#[system]` proc-macro crate that turns an ordinary pure Rust `fn` in
`crates/logic-sandbox` into a registered, ABI-conformant Domain B system: the
macro expands the function body into an exported trampoline living in
`crates/logic-export`, generates a registration-table entry the host can
enumerate, and statically checks that the signature matches the `contracts`
ABI. Authoring a system becomes "write a function, tag it", and everything
mechanical — export naming, the `#[no_mangle]` attribute that cannot sit next
to `forbid(unsafe_code)`, metadata emission, registration — is generated.

Because `#[no_mangle]` is an unsafe attribute, the generated trampolines and the
registry must live in `crates/logic-export`, which exists precisely so that
nothing unsafe ever coexists with `forbid(unsafe_code)` in `logic-sandbox`. The
macro generates *declarations* the user places in `logic-export`; it never
writes `unsafe` itself. The generated code is 100% safe Rust and, like the rest
of Domain B, uses fixed-point math only.

## Core Concepts

### The pure system signature (the ABI)

Every system is the canonical pure form from `contracts`:

```rust
pub type PureSystem =
    fn(&StateView<'_>) -> Result<WorldDelta, RecoverableError>;
```

So an authored system looks like:

```rust
// crates/logic-sandbox/src/systems.rs  (Domain B, forbid(unsafe_code))
use contracts::{RecoverableError, StateView, WorldDelta};
use openengine_math as fx;

#[system(name = "wander", schedule = FixedUpdate)]
fn wander(view: &StateView<'_>) -> Result<WorldDelta, RecoverableError> {
    // read view.columns/arena with bytemuck::cast_slice; fixed-point only ...
    Ok(WorldDelta::default())
}
```

The `#[system]` macro accepts the function unchanged and adds metadata via the
optional attributes below. It does **not** change the function's runtime
behaviour.

### What the macro expands

For a function `fn wander(view: &StateView) -> Result<WorldDelta,
RecoverableError>` the macro emits, in `logic-export`:

1. A **re-export**/pointer declaration of the function so the trampoline crate
   can reach it without pulling the whole logic crate's internals across the
   ABI.
2. A **metadata constant** describing the system (name, schedule phase, query
   list) for host registration and diagnostics.
3. A registration entry pushed into the crate's static registry.
4. *Reference* generated `#[no_mangle]` export bodies that call the pure fn —
   authored only once at the trampoline boundary.

The macro deliberately keeps the actual `#[no_mangle]` trampoline **in
`logic-export`** by generating a small explicit module the developer drops
there, so the "no unsafe attribute next to forbid(unsafe_code)" rule holds:

```rust
// crates/logic-export/src/systems/auto.rs  (generated, committed)
//! Generated by #[system]. Do not edit by hand.
openengine_macros::system_export!(wander);
```

### Compile-time ABI signature check

The macro verifies the function's signature is exactly
`fn(&StateView<'_>) -> Result<WorldDelta, RecoverableError>`. It rejects, at
compile time, functions that:

- take any argument other than `&StateView<'_>`,
- return anything other than `Result<WorldDelta, RecoverableError>`,
- are `async`, `unsafe`, generic over lifetimes in a non-ABI way, or
- close over environment (i.e. are not free functions).

This is implemented by parsing the input `syn::ItemFn` and comparing the
signature to the expected shape, failing with a clear `compile_error!`.

### Optional attributes

```rust
#[system(
    name = "wander",            // default: fn name; must be a valid identifier
    schedule = FixedUpdate,     // default: FixedUpdate (phases from game loop)
    query = Position + Velocity // documented intent; compile-checked where possible
)]
```

- `name` — stable system id used by the host scheduler and diagnostics.
- `schedule` — the `SystemPhase` the host should run it in (`PreUpdate`,
  `FixedUpdate`, `PostUpdate`, `Render`).
- `query` — a human- and agent-readable declaration of which components the
  system reads. This is metadata for the host state-view builder and for the
  Critic; it does not fabricate references across the boundary (queries are
  materialized into a `StateView`, per the ECS spec).

### Registration table

The macro appends each system to a crate-level, fixed-order table. The host
reads this table once at module load to discover and address systems
deterministically:

```rust
// logic-export: a stable, order-preserving table (no HashMap iteration).
pub struct SystemMeta {
    pub name: &'static str,
    pub schedule: SystemPhase,
    pub queries: &'static [ComponentId],   // resolved host-side by registry
}

/// Exported so wasmtime/host can enumerate systems in a deterministic order.
static REGISTRY: &[SystemMeta] = &[
    SystemMeta { name: "wander", schedule: SystemPhase::FixedUpdate, queries: &[] },
    // ...
];
```

The host validates that the ordered registry names match what its scheduler
expects and that no name is duplicated; mismatches are a loud load-time failure.

## The generated trampoline boundary

To keep `no_mangle` exports out of `forbid(unsafe_code)` crates, the design
splits generated output across the two crates:

- **`crates/logic-sandbox`** — the `#[system]`ed pure fns only. The macro here
  may add the metadata but **no** `#[no_mangle]`.
- **`crates/logic-export`** — a `system_export!` companion macro (or the
  generated module above) that, from the *same* function symbol, creates the
  `#[no_mangle] pub extern "C"` trampoline `openengine_system_<name>` that the
  sandbox re-exports. This module is allowed to carry the unsafe attribute;
  `logic-sandbox` never is.

```rust
// logic-export, the only place #[no_mangle] appears for systems:
#[no_mangle]
pub extern "C" fn openengine_system_wander(tick: u64) -> u64 {
    // build a tick_only/tick+columns StateView, call wander, encode with
    // contracts::encode_delta, return a host-readable ptr/len pair.
    crate::trampoline::run(wander_abi_fn, tick)
}
```

This mirrors the existing `logic-export` design (`openengine_tick`), but
per-system, so each tagged fn becomes individually schedulable and hot-reloadable
(see spec `10-hot-reload`).

## Key Rust types / crates

- New proc-macro crate `openengine-macros` (`#[system]`, `system_export!`).
- Generated `SystemMeta` + `static REGISTRY` in `logic-export`.
- Companion `system_export!` producing the `#[no_mangle]` trampoline.
- Reuses `contracts::PureSystem`, `StateView`, `WorldDelta`,
  `RecoverableError`, `ComponentId`, and game-loop `SystemPhase`.

## Constraints

- No `unsafe` introduced anywhere; `no_mangle` confined to `logic-export`.
- Signature is checked at compile time against the ABI; no silent drift.
- Generated code is order-stable and deterministic (no `HashMap` iteration).
- Fixed-point math stays the only math available to authored system bodies.
- Macro must expand in `no_std`; generated metadata uses `&'static` only, no
  runtime allocation.
- Portability: proc-macro crate runs on the host toolchain; expands on
  `x86_64-linux` and `aarch64-linux` identically. `cargo expand` output is the
  source of truth for code review.

## Performance

- The macro's metadata/registry is `static`, so runtime cost is zero.
- The trampoline is a thin call into the pure fn plus the existing
  postcard encode; no additional copy on top of the current ABI bridge.
- No generated indirection beyond a direct fn-pointer call; hot reload swap
  still re-points at the module boundary, not inside the system.

## Testing strategy

- Unit: `#[system]` on a conforming fn compiles and registers one entry with the
  right name/schedule/query; on a non-conforming fn (wrong arg type, wrong
  return, `async`, `unsafe`, generic) it fails with a clear
  `compile_error!` — asserted with a `trybuild` ui test set.
- Expansion test: `cargo expand` output for a sample matches a committed golden
  file (no `unsafe`, correct `no_mangle` location in `logic-export`).
- Integration: author two systems, enumerate the registry in order, run them
  through the wasmtime bridge, apply deltas, verify determinism 3× and
  `verify-wasm-purity` reports `[PURE]`.
- ABI drift test: a fixture that uses a stale signature must not compile,
  proving the wall holds.

## Dependencies

- `proc-macro2`, `syn`, `quote`, `trybuild` (dev), `contracts`,
  `openengine-math`. The macro crate is a normal host crate; its output only
  compiles into Domain B-safe code.
